# vis pack

Builds a library for publishing. `vis pack` runs the `pack` target, so it uses the same target resolution, filters, and caching as `vis run pack`.

A package's own `pack` script in `package.json` always wins. When a project has no `pack` script, vis infers one from its config file:

- `rslib.config.*` → `rslib build`
- `packem.config.*` → `packem build`

A project with a `packem.config.*` also gets `vis build`, the same command. `vis pack` is the name to use for libraries.

## Setting one up

If no project defines a `pack` target, `vis pack` asks which library builder to set up: Rslib or packem. Your choice is the consent. vis installs the tool with `vis add -D` into the chosen project, and adds a `pack` script to its `package.json`. It also writes the tool's config file and `src/index.ts`, unless they already exist.

- **Rslib** installs `@rslib/core` and `typescript`, and writes `rslib.config.mts` with ESM output.
- **packem** installs `@visulima/packem`, `esbuild` (the transformer packem's config uses), and `typescript`, and writes `packem.config.ts` with ESM output and `src/index.ts` as the entry.

A new packem library can fail its first build on `package.json` warnings: missing `exports`, `engines`, or `sideEffects`. packem exits non-zero on warnings by default. Add the fields it names, or set `failOnWarn: false` in `packem.config.ts`.

In a non-interactive run (CI, or no terminal) it stops and lists the options instead.

## Usage

```bash
vis pack [args…] [options]
```

## Examples

```bash
# Build every library that has a pack target
vis pack

# Build one package
vis pack --filter @org/utils

# Forward flags to the pack target
vis pack -- --sourcemap
```

Like `vis dev` and `vis build`, vis treats the directory it runs from as the workspace root. Run it from the root, and use `--filter` when the workspace has several projects.
