# vis preview

Serves the built output. `vis preview` is `vis run preview`, so it uses the same target resolution, filters, and caching.

A package's own `preview` script always wins. Otherwise vis infers one from the config file:

- `vite.config.*` → `vite preview`
- `rsbuild.config.*` → `rsbuild preview`
- `rspack.config.*` → `rspack preview`

Run from a package directory, `vis preview` serves that package. Run from the workspace root, it serves every project that has a `preview` target.

Preview is a long-running server, so it runs in an interactive terminal. In CI or with piped input, vis skips it and reports that instead.

Unlike `vis dev` and `vis build`, `vis preview` does not offer to install a tool. A preview needs a build first, so run `vis build` before it.

## Usage

```bash
vis preview [args…] [options]
```

## Examples

```bash
# Serve the built output across the workspace
vis preview

# Serve one package's build output
vis preview --filter @org/web

# Forward flags to the preview server
vis preview -- --port 4173
```
