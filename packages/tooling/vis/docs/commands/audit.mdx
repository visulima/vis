# vis audit

`vis audit` scans every installed package (resolved from the lockfile, plus the packages some of them ship bundled inside themselves — see [What is scanned](#what-is-scanned)) against the OSV vulnerability database and, when configured, one or more supply-chain intelligence providers — [Socket.dev](https://socket.dev) and [Google deps.dev](https://deps.dev) (the latter ships OpenSSF Scorecard signals + GHSA advisories and needs no API token).

It defaults to the local **offline OSV cache** populated by [`vis advisories sync`](./advisories.mdx) — no network access required at scan time. Falls back to the live OSV API when no cache is present.

## Usage

```bash
vis audit [options]
```

## Quick examples

```bash
# Full audit (offline if a synced cache exists, otherwise OSV API)
vis audit

# Severity gate
vis audit --severity high

# CI / pipeline output
vis audit --format json
vis audit --format sarif          # GitHub code-scanning
vis audit --format csaf           # Enterprise VEX pipelines
vis audit --format cyclonedx-vex  # SBOM + VEX in one document
vis audit --format gitlab         # GitLab CI dependency-scanning widget
vis audit --format junit          # JUnit XML (GitLab/Actions/Jenkins test reporters)

# Self-contained HTML report (auto-opens in a TTY)
vis audit --report ./audit-report.html

# Reachability filter — only flag vulns in statically-imported packages
vis audit --usage

# Fix loops (dry-run preview by default)
vis audit --show-fixes             # print fix suggestions (no apply, no rescan)
vis audit --fix                    # upgrade direct deps + rescan
vis audit --fix --yes              # non-interactive (required in CI)
vis audit --fix --allow-major      # permit major-version bumps
vis audit --fix-transitive         # write PM-specific overrides

# CI exit gates
vis audit --exit-code              # exit 1 on any finding
vis audit --fail-on high           # exit 1 on high/critical only

# Accepted-risk handling
vis audit --show-accepted          # include acknowledged risks
vis audit --sync                   # mirror accepted risks to native PM config

# Supply-chain policy engine
vis audit --policies license,vulnerability  # narrow to a subset for this run
vis audit --policies none                   # skip the policy engine entirely
```

## What is scanned

The scan starts from the lockfile: every package it lists, once per `name@version`. A lockfile never lists some packages, though, and `vis audit` reads those from `node_modules`, so install first. In a checkout with no `node_modules` (lockfile only) there is nothing to read, and only the lockfile is scanned; the output does not say so.

### Bundled dependencies

A package can declare `bundleDependencies` (or `bundledDependencies`) in its `package.json`. Its package manager then installs those dependencies inside it, at `node_modules/<package>/node_modules/<dependency>`, and no lockfile lists them. `vis audit` reads them for every locked package that is installed, with no option to turn it on:

- the declaration is an array of names, or `true`, which means every entry of `dependencies`;
- a bundled package that itself bundles is followed;
- under pnpm the package is read from its real directory in `node_modules/.pnpm`, whatever the directory is called;
- a copy the lockfile also lists is scanned once, and a finding in it still names the host that ships it;
- `--prod-only` leaves out the bundled copies of a package it leaves out, since they only exist because of that package.

A finding in a bundled copy counts like any other: it is listed, it follows `--severity`, `--fail-on` and `--exit-code`, and an accepted risk for `name@version` covers it. The dependency path of the finding runs from your workspace through the package that ships the copy:

```text
my-app > some-tool@4.2.0 > bundled-dep@2.5.0
```

Three flags treat a copy shipped inside another package differently, because it is not a dependency you declared:

- `--usage` asks whether your workspace uses the package that ships it (the top-level host), since nothing imports the bundled name.
- `--fix` and `--fix-transitive` leave it out of their plans and say so: an override does not replace a copy a package ships inside itself. Upgrade the package that ships it.
- The policy engine (`--policies`) still judges only the packages the lockfile lists.

### Vendored copies: what is not scanned

Some packages ship copies of other packages with no declaration, in a tree such as `dist/compiled`. When such a directory has a `package.json` with a name and a version, `vis audit` scans it like a bundled copy. When it has no version, or no `package.json`, there is nothing to match an advisory against, and the version is never guessed. These are reported as **not scanned**, never as having no issues.

`vis audit` looks in `dist/compiled` and `compiled` of each installed package. Every other place a package can hide code (a bundled `dist` file, a Git submodule, a binary) is outside what it can see.

A bundled dependency whose manifest cannot be read (no file, or no name or no version) is reported the same way.

### Reading the "not scanned" lines

```text
Not scanned: next@16.3.8 vendors 126 packages without versions (dist/compiled)
Not scanned: some-tool@4.2.0 bundles 2 packages whose manifest cannot be read (a, b)
```

One line per host and place. They tell you that the result is about the packages that were scanned, not about everything the project ships, so a run with such a line says `No known issues in the scanned packages` instead of `No security issues found`. They are a notice only: they never change the exit code.

To act on one, check the advisories of the host package directly, or upgrade it: a newer release may ship versioned copies or fixed ones.

| Format           | Where the information is                                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| table            | The lines above, under the scan summary; the clean message changes as described.                                                                                                                                     |
| `json`           | A new last key, `unauditable`: an array of `{ count, host, kind, location }` (`kind` is `vendored` or `bundled-unreadable`; the latter also has `names`). Empty when nothing was left out. `schemaVersion` is `1.1`. |
| `--report` HTML  | A "Not scanned" list under the summary, the same `unauditable` array in the embedded JSON, and `No known issues in the scanned packages` in the clean state.                                                         |
| `sarif`          | One `note` per line in `runs[0].invocations[0].toolExecutionNotifications`; a finding in a bundled copy says `(bundled in host > package)` in its message.                                                           |
| `junit`          | A finding in a bundled copy says `Bundled in: host > package` in its failure text. The lines are not part of the report.                                                                                             |
| `cyclonedx-vex`  | A bundled package that no lockfile lists is added to the BOM as a component, with the host that ships it depending on it, so every `affects` reference resolves. The lines are not part of the report.               |
| `csaf`, `gitlab` | A finding in a bundled copy is listed as plain `name@version`; these schemas have no place for the host or for the lines, and are unchanged.                                                                         |

## Options

### Filtering and scope

| Option               | Default | Description                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--severity <level>` | `low`   | Minimum severity to report: `low`, `medium`, `high`, `critical`.                                                                                                                                                                                                                                                                                                                |
| `--prod-only`        | `false` | Skip devDependencies — scan production graph only (also the packages they bundle).                                                                                                                                                                                                                                                                                              |
| `--usage`            | `false` | Reachability filter — only report packages that are statically imported (for a bundled copy: whose host is).                                                                                                                                                                                                                                                                    |
| `--no-usage`         | `false` | Disable the reachability filter even if enabled in config.                                                                                                                                                                                                                                                                                                                      |
| `--ecosystem <list>` | `npm`   | Comma-separated ecosystems: `npm`, `pypi`, `crates.io` (or `cargo`), `maven` (or `gradle`), `go`, `rubygems`, `packagist` (or `composer`), `hex`, `nuget`, `pub` (or `dart`), `swift` (or `swifturl`). Non-npm ecosystems require `--offline` (the online OSV path is npm-only). `zig` is refused; see [Ecosystems that cannot be audited](#ecosystems-that-cannot-be-audited). |
| `--show-accepted`    | `false` | Include findings already on the workspace's accepted-risk list.                                                                                                                                                                                                                                                                                                                 |

### Ecosystems that cannot be audited

**Zig** cannot be audited. OSV has no Zig ecosystem, and the GitHub Advisory Database does not cover Zig either, so there is no advisory source to match against. `vis audit --ecosystem zig` is refused with an error, so a clean result is never reported for packages that were not checked. Zig packages still appear in `vis sbom`, with the limits described there.

### Offline lock files

With `--offline`, each ecosystem named in `--ecosystem` must have its lock file present. If one is missing, the run fails with exit code 1 and names the missing file before anything is scanned, so a missing lock file is never reported as a clean result. An ecosystem whose lock file exists but lists no packages passes.

### Output formats

| Option                   | Description                                                                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--format table`         | Default human-readable output.                                                                                                                                      |
| `--format json`          | Machine-readable JSON (for CI integration).                                                                                                                         |
| `--format sarif`         | [SARIF 2.1.0](https://docs.oasis-open.org/sarif/sarif/v2.1.0/) — for GitHub / GitLab code-scanning.                                                                 |
| `--format csaf`          | [CSAF 2.0](https://oasis-open.github.io/csaf-documentation/) `csaf_vex` profile.                                                                                    |
| `--format cyclonedx-vex` | [CycloneDX 1.7](https://cyclonedx.org/specification/) BOM with `vulnerabilities[]` (SBOM + VEX in one document).                                                    |
| `--format gitlab`        | [GitLab dependency-scanning report](https://docs.gitlab.com/ee/development/integrations/secure.html) v15.2.1 — picked up by the Secure stage's Dependencies widget. |
| `--format junit`         | Surefire-flavoured JUnit XML — parsed by GitLab, GitHub Actions test-reporter, Jenkins, etc., without a plugin.                                                     |
| `--report <path>`        | Write a self-contained HTML report to `<path>`. Auto-opens in a TTY when not in CI.                                                                                 |

**Native fast path.** In a CI context with no terminal, at the root of a pnpm workspace without a `vis.config`, the Rust binary answers `vis audit --format json --policies none` (with at most one each of `--severity <level>`, `--fail-on <level>` and `--exit-code`) without starting Node, but only for a scan that finds nothing: OSV lists no vulnerability, or answers with a status outside 2xx (which the Node scan also reads as "no findings"). It prints the same report and the same `none found` row on stderr as Node, over its own HTTPS client with the same 10 second limit. The binary hands the run to Node before anything is printed for: every other format and flag (without `--policies none` the default `publisherChange` policy asks the registry for every package, which the binary does not do), an answer that lists a finding or that is not the JSON object Node reads the same way, a request that fails or is redirected, a proxy, CA or Node option in the environment (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NODE_USE_ENV_PROXY`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `SSL_CERT_DIR`, `NODE_TLS_REJECT_UNAUTHORIZED`, `NODE_OPTIONS`), `VIS_AUDIT_BACKEND` or `VIS_INSTALLER` in the environment, a `packageManager` pin, an `auditConfig` in `pnpm-workspace.yaml`, a lock file with no package, a lock file or package name it does not read exactly, and an installed package that [bundles dependencies or vendors a tree of packages](#what-is-scanned) (any package under `node_modules` that declares `bundleDependencies` or has a `dist/compiled` or `compiled` directory with a subdirectory). The binary reads the lockfile only, so it leaves that scan to Node rather than print a report that counts fewer packages. A workspace with none of these is still answered natively. Node then asks OSV itself.

### Offline cache

| Option        | Default                            | Description                                                     |
| ------------- | ---------------------------------- | --------------------------------------------------------------- |
| `--offline`   | `false`                            | Query the local OSV cache only. Errors if the cache is missing. |
| `--db <path>` | `<cache>/vis/advisories/db.sqlite` | Override the offline advisory DB path.                          |

Run [`vis advisories sync`](./advisories.mdx) to populate the cache.

### Fix loops

| Option             | Default | Description                                                                                                                                       |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--show-fixes`     | `false` | Print fix-suggestion lines next to each finding (no apply, no rescan).                                                                            |
| `--fix`            | `false` | Upgrade direct deps for vulnerable packages by running the active PM update command, then rescan. Dry-run preview shown first.                    |
| `--fix-transitive` | `false` | Write PM-specific overrides for vulnerable transitives (pnpm-workspace.yaml / package.json overrides / resolutions). Dry-run preview shown first. |
| `--yes`            | `false` | Skip the confirmation prompt. **Required in CI for both `--fix` and `--fix-transitive`.**                                                         |
| `--allow-major`    | `false` | Allow `--fix` to bump a direct dep across a major version when the lowest fix is outside the existing range.                                      |

### CI exit gates

| Option              | Default | Description                                                                          |
| ------------------- | ------- | ------------------------------------------------------------------------------------ |
| `--exit-code`       | `false` | Exit 1 if any actionable issue is found.                                             |
| `--fail-on <level>` | —       | Exit 1 only when a finding is at this severity or higher.                            |
| `--sync`            | `false` | Sync vis accepted risks to native PM config (`pnpm-workspace.yaml` / `.yarnrc.yml`). |

### Supply-chain policy engine

| Option               | Default                 | Description                                                                                                                                                                                                                                         |
| -------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--policies <names>` | every configured policy | Comma list of policies to evaluate this run. Pass `none` to skip the engine entirely, `all` to force every known policy. Known: `malware`, `firstSeen`, `unexpectedDeps`, `publisherChange`, `installScripts`, `score`, `vulnerability`, `license`. |

### Backend selection

| Option             | Default | Description                                                                                                                                                                                                                                                         |
| ------------------ | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--backend <name>` | `auto`  | Vulnerability scanner backend. `auto` delegates to `aube audit` when aube is the active installer; `aube` forces delegation (errors if `aube` is not on `PATH`); `vis` always uses the built-in OSV scanner (plus any configured providers — Socket.dev, deps.dev). |

Resolution: CLI `--backend` → `VIS_AUDIT_BACKEND` env → `security.audit.backend` in `vis.config.ts` → `auto`.

### AI explanations

| Option                | Default | Description                                                                                                                                                                                                                                         |
| --------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--explain [id\|idx]` | —       | Add a plain-English AI explanation to findings. Bare flag explains all findings at/above `--severity`; pass a finding index (e.g. `2`) or a CVE/GHSA id to explain just one. Auto-detects an installed AI CLI; mutually exclusive with `--offline`. |

Vis-only features (`--report`, `--fix-transitive`, `--usage`, `--policies`, `--format sarif|csaf|cyclonedx-vex|gitlab|junit`, `--ecosystem` beyond `npm`) print a warning and are dropped when delegating; pass `--backend vis` if you need them.

The policy engine wraps eight Socket.dev-style supply-chain gates. Each policy
is opt-in via the corresponding `security.policies.<name>` field — leaving the
field unset means the engine skips that policy entirely. `block`-severity
decisions feed into `--exit-code` and `--fail-on` the same way vulnerability
findings do.

This release ships four offline-clean policies:

| Policy           | What it does                                                                          |
| ---------------- | ------------------------------------------------------------------------------------- |
| `license`        | SPDX allow / deny lists. Deny wins on any sub-expression match in SPDX expressions.   |
| `installScripts` | Wraps the existing `allowBuilds` / `strictDepBuilds` scan; surfaces unapproved hooks. |
| `vulnerability`  | Surfaces OSV findings; `failOn` controls block vs. warn severity.                     |
| `unexpectedDeps` | Allow-list of acceptable transitives + baseline lockfile diff.                        |

Network-bound policies (`malware`, `firstSeen`, `publisherChange`, `score`)
plug into the same engine in a follow-up commit.

## Fix loops in depth

The two fix loops are intentionally separated by surface:

| Loop               | Touches                                                      | When to use                                                                          |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `--fix`            | Direct deps in each `package.json` (every workspace member). | The vulnerable package is listed in your manifest.                                   |
| `--fix-transitive` | PM-specific override surface (one file).                     | The vulnerable package is pulled in by a transitive — your manifest doesn't list it. |

Both loops:

1. Build a plan from current findings.
2. Print a dry-run preview (which files / packages will change).
3. Prompt for confirmation (interactive TTY) or honour `--yes` (CI).
4. Apply, then re-scan to verify the issue is gone.

In CI, `--fix-transitive` requires `--yes` **and** `security.audit.apply.transitive.enabled = true` in `vis.config.ts` — a two-lock design so you don't end up rewriting overrides on every PR by accident.

## Configuration

`vis.config.ts`:

```ts
import { defineConfig } from "@visulima/vis/config";

export default defineConfig({
    security: {
        audit: {
            // Default to the offline OSV cache when present.
            offlineByDefault: true,
            apply: {
                transitive: {
                    // CI gate — required alongside `--yes` before overrides are written.
                    enabled: false,
                },
            },
        },
        policies: {
            vulnerability: {
                // CI exit gate (overridable via --fail-on).
                failOn: "high",
                usage: {
                    // Apply the reachability filter by default.
                    enabled: true,
                },
            },
            license: {
                // SPDX allow / deny lists. Deny wins on any sub-expression
                // match within an SPDX expression (`(MIT OR GPL-3.0)`
                // is blocked when GPL-3.0 is on the deny list).
                allow: ["MIT", "Apache-2.0", "BSD-3-Clause", "ISC"],
                deny: ["GPL-3.0", "AGPL-3.0"],
            },
            installScripts: {
                // Build-script approval surface (mirrors pnpm allowBuilds
                // / strictDepBuilds). Strict mode blocks the install
                // when any dep declares an unapproved lifecycle script.
                allow: { esbuild: true, "@swc/core": true },
                strict: true,
            },
            unexpectedDeps: {
                // Net-new transitive detection. Either provide a
                // static allow list, a baseline lockfile path, or both
                // (intersection is enforced).
                baselineLockfile: "./security/baseline.pnpm-lock.yaml",
            },
        },
        socket: {
            enabled: true,
        },
        depsDev: {
            // No auth required. Pulls OpenSSF Scorecard signals +
            // GHSA advisories from api.deps.dev. Heavily cached
            // (24h project data, 7d versions + advisories).
            enabled: true,
        },
        // When both providers are enabled, this controls which one's
        // `score` wins on merge. Alerts from the secondary are still
        // appended and deduped by `key`.
        primaryProvider: "socket",
        // Workspace-scoped acknowledged risks (shared across all policies).
        acceptedRisks: {
            "some-package": {
                reason: "Vendor confirmed no fix available",
                acceptedAt: "2026-01-01",
                expiresAt: "2026-12-31",
            },
        },
    },
});
```
