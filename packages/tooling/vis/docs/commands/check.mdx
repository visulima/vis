# vis check

Runs `vis lint` and then `vis fmt --check` over the same scope, so one command gates a change on every source check. The TypeScript type check runs too when TypeScript is detected in the workspace, unless `lint.adapters.typecheck.enabled` is set to `false`.

Dependency checks moved to [`vis outdated`](./outdated).

## Usage

```bash
vis check [files…] [options]
```

With no files, the whole workspace is checked. Pass file paths to check a subset.

## Examples

```bash
# Lint, check formatting, and type-check the workspace
vis check

# Apply lint fixes and formatting in place
vis check --fix

# Check a specific file
vis check src/foo.ts

# Only check files staged in the git index
vis check --staged

# Only check files changed vs the main branch
vis check --since main
```

## Options

| Option     | Default | Description                                                    |
| ---------- | ------- | -------------------------------------------------------------- |
| `--fix`    | `false` | Apply lint fixes and formatting in place instead of reporting |
| `--since`  |         | Only check files changed vs the given git ref                  |
| `--staged` | `false` | Only check files currently staged in the git index             |

For per-tool output formats (JSON, SARIF, JUnit, GitHub), run `vis lint` or `vis fmt` directly.

## Exit codes

Exits `1` when the linter reports errors, the type check fails, or the formatter would change a file (in check mode, without `--fix`).
